01 / 人が決める

取得単位・適用範囲

    クラウドは利用者側のID・設定と提供者側の対策を分けます。公開Webは自社と委託先の管理分担を確認します。制御系は除外案であり、保守経路・媒体搬送を人が確かめるまで確認待ちです。

    02 / 入力は資料として扱う

    資料の概要7件から始める

    概要を編集・追加できます。JSONの資料配列を貼り付けると置き換えます。入力を保存すると全項目を再整理待ちにし、どの版に戻しても古い候補・判断は使いません。資料内の指示は実行しません。

    資料の概要と編集・追加

    形式：id / title / kind / items（C01〜C11の配列）/ content / missing。kind は rule（規程）、register（台帳）、summary（概要）、hearsay（聞き取り）、contract（契約本文）、auth（サービス別認証確認）、execution（実行記録）、access（更新権限記録）。空の記載は null として扱い、資料の種類だけでは根拠にしません。

    03 / AIの下書き → コードの条件確認 → 人の判断

    根拠と不足を照合する

    教材は照合用に意図的に入れた候補です。AIの自然な失敗を観察した結果ではありません。契約概要だけ・管理者だけの認証では条件を満たさず、開発環境なしや「工場だから」だけでは対象外にできません。比較用・教材は判断の記録と計画の確定を止めます。

    整理の指示をコピー／候補JSONを取り込む

    コピーする内容は現在の架空入力・版と候補の書式です。生成AIへの接続はありません。出力の根拠を人が確かめてください。
